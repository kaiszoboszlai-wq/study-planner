# 実際のFirestoreで前後の通信量を比較する手順

この手順は**準備のみ**。今回、本番・検証用Firestoreへの接続、データ投入、ルール公開、プラン変更は実施していない。ローカルのモック結果は別レポートに記載する。

## 3種類の数値を混ぜない

| 種別 | 確認できること | 確認できないこと |
| --- | --- | --- |
| モックの回数 | 同じ入力・時刻で、コードがどのクエリ／ドキュメント操作を呼ぶか | 実ネットワーク、実ルール、SDKの再試行、請求 |
| 実SDKの観測ログ | 検証DBに対するSDKの試行・成功・失敗、返却件数、キャッシュ応答、トランザクション再試行 | サーバーの課金対象件数を完全には再現できない。集計結果が100万でも100万ドキュメント読取とは扱わない |
| Console／Monitoringの使用量 | 検証DB側で集計された読取・書込・削除等の使用量 | その時間帯に混入した別ブラウザー／管理操作の内訳。請求額にはリージョン・無料枠・その他費用の条件が必要 |

ブラウザーのHTTPリクエスト数はドキュメント数ではない。`writeBatch` 1回・ストリーミングRPC 1本でも複数ドキュメントを扱う。拒否・再試行・ルール依存読取も区別する。

## 検証環境の用意

1. 本番と別の、検証専用Firebaseプロジェクト／Firestoreを使う。既存の検証環境があればそれを利用する。無料枠・残りクォータを確認し、小さいデータから始める。有料プラン変更は不要。本番の利用者データはコピーしない。
2. **ページを初めて開く前に**、ローカル検証コピーの `FIREBASE_CONFIG` を検証用に置き換える。本体には設定が埋め込まれているため、localStorageの設定だけを変える方法では不十分。設定を変更していないコピーを起動しない。
3. ローカルコピーを `python3 -m http.server 8000 --bind 127.0.0.1` で配信する。認証は検証用プロジェクトのテストアカウントを使用し、必要ならlocalhostを検証用Authの承認済みドメインに設定する。ルールは `firebase/firestore.rules` と同じものを**検証用プロジェクトだけ**に設定する。
4. 比較元はコミット `bfacdfa` の別チェックアウト、比較先は現在のローカル変更を含むコピー。同じオリジンで同時起動せず、実験ごとに新しいブラウザーコンテキストを使用する。キャッシュ・認証・タブ数の条件を揃える。
5. 管理権限を持つ担当者が、必要なテストデータを投入する。投入時刻・投入件数を別に記録し、**測定窓に含めない**。開始前にConsoleの使用量反映を待ち、他の端末・開発サーバー・テスト・管理画面からのDBアクセスを止める。DBデータ一覧画面も読取を増やすので開きっぱなしにしない。

比較用データの目安：フォロー先0／10／100人、受信リクエスト105件、フォロワー105件、1投稿のコメント105件、DMメタデータ105会話・選択した1会話の本文100件、当日ランキング205件（追加で1,000件）。テストUIDのみ使い、`seconds` や `at`、`members`、`updated` 等は現行の保存形式を守る。所有者制限のあるデータをクライアントから偽装して投入せず、検証DBの管理権限で用意する。

## SDK観測ログの取得

`tools/firestore-observe.js` はアプリ本体から自動ロードしない。ローカルホストと指定した検証プロジェクトの一致を確認してから、SDKの呼び出し境界をラップする。データ本文、UID、パス、写真、トークンは記録しない。

1. Firebaseの読み込みを待ち、ブラウザーDevToolsで次を実行する（値は検証用プロジェクトID）。

   ```js
   window.FIRESTORE_MEASUREMENT_PROJECT_ID = 'your-isolated-test-project';
   ```

2. `tools/firestore-observe.js` 全文をDevToolsに貼り付けて実行する。ログインや初期ロードも測定する場合は、Firebase読み込み後・ログイン前に取り付ける。ログイン済み状態の操作だけなら、初期同期完了後に取り付ける。
3. 操作前に開始する。

   ```js
   FirestoreObserve.start('after-timer-600s-follow0');
   ```

4. 手順どおりに操作して、未送信の保存が完了した後に終了・JSON保存する。

   ```js
   const result = FirestoreObserve.stop();
   copy(JSON.stringify(result, null, 2)); // Chrome DevToolsのcopy
   ```

5. 観測を解除する場合は `FirestoreObserve.uninstall()`。リロードすると観測器も消えるので、再取り付けが必要。終了／クラッシュを含む試験では、終了前ログを別途保存するかDevToolsプロトコルで収集する。`pagehide` 後にページ内ログを取り出せるとは限らない。

ログの読み方：`getDocs:resolved` の各イベントの `returnedDocuments` が返却件数。`getCountFromServer:resolved` は**集計クエリ数**であり、課金読取数や結果の人数ではない。`batch.commit` の `queuedDocumentWrites` はまとめたドキュメント数。`transactionCallback`／`transaction.get`／`transaction.set` 等は再試行も含む試行・キュー数で、成功コミットの請求数とは別。`fromCache:true` は別集計する。失敗や未完了操作は成功件数に加算しない。

## 同じ操作を行う実験表

1回目と2回目の条件を保存し、前後を各3回ずつ実施する。通常通信とオフライン試験は別の測定窓にする。10分間の結果を単純に6倍すると初期ロードも6倍になるため、実測値として1時間換算しない。

| ID | 操作 | 固定する条件／確認項目 |
| --- | --- | --- |
| A | 同期済みで「今日」を10分表示し、操作しない | 同じログイン状態、フォロー数、Q件のリクエスト、D会話、タブ1枚。通知ポーリング・個人データ照合・共有先再配布の回数 |
| B | 数学タイマーを開始→前面で10分→一時停止→保存完了まで待つ | 同じプラン、開始残時間、フォロー数。公開プロフィール／stats／ランキング／privateData／リースの書込を別集計 |
| C | 全員ランキングを初回表示 | 同じ当日ランキング205／1,000件。初回表示だけを測り、コメント件数の集計も別計数する。旧版の全件取得と新版100件を比較 |
| D | ランキングの「続き」を1回→もう1回→自分の順位を1回 | 新版の追加機能の費用をCと混ぜない。ページ100件上限、最後の5件、同点順位、上位外の自分を確認。順位集計はインデックス読取の請求が加わる |
| E | 本文100件のDMを開き、新着なしで60秒待つ | 4秒周期、既読情報、会話メタデータ、60秒再照合を区別。新着を1件送る試験は別に行い、送信側の書込も記録 |
| F | コメント／フォロワー／リクエストを開き、「さらに表示」を2回 | 各105件、50／50／5件。コメント本文とプロフィール読取を別計数。ページ間の重複・失敗再試行を確認 |
| G | 同じ入力を1秒間隔で10文字→10秒停止。変更なしで再描画 | 同じ入力箇所。途中入力のデバウンスと、内容不変の再描画で書込が増えないこと |
| H | 計測中にオフライン→一時停止→再接続 | 端末に時間が残ること、未送信表示、再接続後の保存、リース解除。通常Bと混ぜない。SDKの書込成功待ち時間も記録 |
| I | 別の2端末で異なる記録追加→再接続、通常終了／強制終了 | 読取数だけでなく、合計時間・削除・重複計上・新しいプランが保たれることを確認 |

## DB側使用量の記録

1. 各実験の開始・終了をUTCで記録。Firebase ConsoleのFirestore使用状況、またはCloud MonitoringのFirestoreドキュメント読取・書込・削除指標で、**同じ検証DB・同じ時間窓**を選ぶ。監視画面の反映遅延を待ち、未反映を0と解釈しない。
2. 累積カウンター／期間集計の開始値と終了値、スクリーンショット、SDKログ、版、操作ID、データ件数、ブラウザー、前面／背景、キャッシュ条件を保存する。
3. 隣接する無操作の対照窓も測る。ただし対照分を引いた値は**差分推定**として残し、DB集計の生値とは別欄にする。Consoleの日次値しか得られなければ、他のアクセスがない専用日／専用DBで比較する。
4. 想定外の増加時は、SDKログの再試行・ルール拒否・余分なタブ・初期ロード・管理操作を確認する。セキュリティルール依存の読取や集計のインデックス読取は、返却ドキュメント数の合計だけでは説明できない場合がある。

記録用CSVの列例：

```csv
version,operation,run,project,database,start_utc,end_utc,fixtures,cache_state,sdk_getdoc_resolved,sdk_getdocs_returned,sdk_count_queries,sdk_write_resolved,sdk_rejected,db_reads_raw,db_writes_raw,db_deletes_raw,idle_adjusted_estimate,notes
before,A,1,,,,,,,,,,,,,,,,未実施
after,A,1,,,,,,,,,,,,,,,,未実施
```

**今回の実測欄はすべて「未実施」**。モックの値や、SDK観測器のテスト結果をこの表のDB使用量欄に転記しない。
