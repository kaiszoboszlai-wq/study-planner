# 全ユーザーランキング用Firestoreルール

`firestore.rules` は、ユーザー提供の既存ルールを保持してランキング用のルールを追加した全文です。

Firebaseコンソールの **Firestore Database → ルール** で、既存の
ルール全文を `firestore.rules` の内容に置き換えて公開します。
`stats`、`privateData`、フォロー承認、メッセージのルールはそのまま維持します。

保存先は `dailyRankings/YYYY-MM-DD/users/ユーザーUID` です。
ログインしたユーザーはランキングを閲覧でき、自分のドキュメントだけを更新できます。
保存するのは表示名・アイコン・色・小さな写真・その日の合計秒数・計測中フラグ・更新日時です。
科目別の学習記録、学校名、目標、成績、メールアドレスは含めません。
全ユーザーランキングの名前・アイコンから開くプロフィールも、この公開データを使います。
プロフィールから従来のフォロー申請・取消ができ、承認後は「フォロー中」と表示します。

ルール公開後、更新版のアプリでログイン・記録同期したユーザーから順に掲載されます。
旧バージョンしか使っていないユーザーのデータは自動で移行されません。
タイマー計測中は表示中のアプリから約1分ごとに更新します。
日付と日別記録は既存アプリと同じく、各端末のローカル日付を使います。
全ユーザーランキングは学習秒数の多い上位100件と自分を表示します。
「続きの100件を表示」で追加取得できます。自分が取得範囲外の場合も「自分の順位を確認」で、上位件数の集計により確認時点の順位を取得できます。正確な総参加者数は常時集計しません。
全件取得による通信量を抑えるための変更で、ルールや保存形式は変えていません。
通信経路と検証結果の詳細は [Firestore監査レポート](../docs/firestore-cost-audit.md) にあります。

この作業環境にはFirebaseの管理用認証がないため、Firebaseへのルール公開は未実施です。
Firebaseコンソールで統合済み全文の公開を行う必要があります。
全ユーザーランキングでも、コメント送信には従来どおりフォローの承認が必要です。

## ルールの検証

ローカルのFirestoreエミュレーターに `firestore.rules` を読み込んでから
`python3 tests/ranking_rules.py` を実行します。テストは
`127.0.0.1:8085` の `demo-study-planner` だけに接続します。
